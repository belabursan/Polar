==================================================================
PROJECT DESCRIPTION: Polar — Sailboat Performance Polar Diagram App
==================================================================

1. PROJECT OVERVIEW
-------------------------------------------------------------------
Polar is a native Android application that interfaces with a sailboat's
NMEA 2000 (N2K) network via an onboard Actisense W2K-1 Wi-Fi Gateway.
The app continuously captures telemetry, saves it to a local historical
database, and uses that information to build a rolling "target speed"
performance model. Live performance data is rendered over a custom
360-degree polar canvas. It also tracks GPS position so recent sailing
runs can be reviewed as a speed-colored trace on a nautical map.

Because the Actisense W2K-1 assembles multi-packet messages natively and
can emit them as plain-text "N2K ASCII", the app reads pre-assembled,
human-readable messages straight off the network — no fast-packet /
multi-packet reassembly is needed in the app.


2. HARDWARE & PROTOCOL SPECIFICATION
-------------------------------------------------------------------
Hardware interface
  * Device: Actisense W2K-1 Gateway on the boat's NMEA 2000 backbone.
  * Network: Wi-Fi, either Access Point mode (direct connection to
    192.168.4.1) or Client mode (connected to the boat's router).
  * Transport: continuous network stream over TCP or UDP, configurable
    via the Actisense Web Interface (default data server ports
    60001-60003).

Data protocol & parsing
  The app is built around the "N2K ASCII" output format. It targets the
  following Parameter Group Numbers (PGNs):

  Performance data:
    * PGN 128259 (Speed, Water Referenced) -> Boat Speed Over Water (SOW)
    * PGN 130306 (Wind Data)               -> True Wind Speed (TWS),
                                               True Wind Angle (TWA)
  Position data (for tracking):
    * PGN 129025 (Position, Rapid Update)  -> latitude / longitude
    * PGN 129026 (COG & SOG, Rapid Update) -> Course Over Ground (COG),
                                              Speed Over Ground (SOG)
    * PGN 127250 (Vessel Heading)          -> true heading (bow direction)

  The protocol layer is designed to be extensible: NMEA 2000 is the only
  protocol now, but additional protocols can be added later behind the
  same interface.


3. ARCHITECTURE
-------------------------------------------------------------------
The application is built as an Android multi-module Gradle project. The
guiding principle is DEPENDENCY INVERSION for portability: all contracts
(interfaces + domain models) live in a single pure-Kotlin module, :core.
Every other module depends ONLY on :core's interfaces — never on each
other directly. A thin :app module wires concrete implementations
together at runtime. This makes individual modules (e.g. communication)
liftable into other projects with minimal change, and allows swapping
implementations (Wi-Fi -> Bluetooth, NMEA 2000 -> another protocol)
without touching the rest of the system.

Technical stack
  | Concern        | Technology                                       |
  |----------------|--------------------------------------------------|
  | Language       | Kotlin                                           |
  | Async spine    | Kotlin Coroutines + Flow                         |
  | UI             | Jetpack Compose (Canvas API for the polar plot)  |
  | Networking     | Java sockets / Ktor (long-lived socket thread)   |
  | Persistence    | Room (over SQLite)                               |
  | Settings store | Jetpack DataStore                                |
  | Maps           | osmdroid (OSM base + OpenSeaMap seamark overlay) |
  | DI             | Hilt (in :app; pure modules stay framework-free) |

Build defaults
  * minSdk 26, latest compileSdk.
  * Kotlin DSL build scripts + a libs.versions.toml version catalog.
  * The continuous socket runs inside an Android foreground Service so
    the OS does not kill the stream.


4. MODULES (12)
-------------------------------------------------------------------
1.  :app
    Android entry point. MainActivity, dependency wiring (Hilt), the
    foreground Service host, and the factory that reads Settings to
    instantiate the correct Transport and protocol parser at runtime.
    Glue only — not intended to be portable.

2.  :core                                              [pure Kotlin]
    The contracts hub. Depends on nothing. Holds all domain models
    (TelemetrySample(sow, tws, twa, timestamp),
     PositionFix(lat, lon, timestamp, sog, cog, heading), Run,
     Settings, ...) and all interfaces:
      Transport, TelemetrySource, PositionSource,
      SampleRepository, TrackRepository, SettingsRepository, Logger.

3.  :comm:transport                                    [pure Kotlin]
    Raw transport. Opens the link and emits framed Flow<String>. Knows
    nothing about NMEA. Wi-Fi (TCP/UDP to the W2K-1) now; Bluetooth
    later — both behind the Transport interface. Includes connection
    state and reconnect handling.

4.  :comm:nmea                                         [pure Kotlin]
    N2K ASCII parser. Receives a Transport by constructor injection and
    parses lines into domain data:
      performance PGNs (128259, 130306)        -> TelemetrySample
      position PGNs    (129025, 129026, 127250) -> PositionFix
                                                   (lat/lon, SOG, COG, heading)
    Implements TelemetrySource and feeds PositionSource. Unit-testable
    against captured sample lines.

5.  :logic:timing                                      [pure Kotlin]
    1 Hz throttling / sampling clock for the incoming stream.

6.  :logic:filtering                                   [pure Kotlin]
    Data cleansing to protect target accuracy: pause or drop logging on
    unsustainable spikes (waves), during tacks/jibes, or when an active
    engine PGN is detected on the network.

7.  :logic:calculation                                 [pure Kotlin]
    Aggregates samples into a matrix keyed by True Wind Speed (0-30 kn)
    x True Wind Angle (1-360 deg), tracking the maximum SOW per cell,
    and derives the per-wind-tier target curves.

8.  :data                                              [Android]
    Room persistence. Implements SampleRepository (telemetry history)
    and TrackRepository (recorded runs). Single owner of the database.

9.  :ui                                                [Android]
    Jetpack Compose. Renders:
      * Polar canvas: 30-degree radial axes, concentric 0-30 kn rings,
        multi-colored per-wind-tier target polylines, and a live marker
        plotting instantaneous TWA/TWS/SOW over the targets.
      * Map screen (osmdroid): OSM base layer + OpenSeaMap seamark
        overlay, showing recent runs as a speed-colored trace.
    Observes Flow<Settings> for scale, color, language, night mode, etc.

10. :logging                                           [Android]
    App diagnostic logging (separate from telemetry data). Rolling files
    sized by the configurable logFileSize setting (default ~1 MB) with
    rotation; gzip compression; export by email (share intent with the
    compressed log attached). Implements Logger; reads its size cap from
    :config so changes apply without a restart.

11. :config                                            [Android]
    User/app settings persisted with Jetpack DataStore, exposed
    reactively as Flow<Settings>. Implements SettingsRepository.
    Settings:
      * protocol        (enum Protocol { NMEA2000 }, extensible)
      * comm type       (enum CommType { WIFI_TCP, WIFI_UDP, BLUETOOTH })
      * ui: scale, color/theme, language, night mode
      * tracking on/off
      * trackInterval (position sampling rate, 1-5 s; default 1 s)
      * speed-color bands (e.g. 0-3 kn yellow, 3-6 kn orange, ...)
      * seamarks overlay on/off, base-map source
      * logFileSize (rolling log-file cap)

12. :tracking                                          [pure Kotlin]
    Groups PositionFix values into "runs", keeps the last 3 (evicts the
    oldest), and maps each segment's speed to a color band (read from
    :config). Samples position at the configurable trackInterval (1-5 s).
    Each point retains SOG, COG and heading for on-map display. Gated by
    the tracking on/off flag. Consumes a
    PositionSource and merges two sources with N2K preferred and the
    phone GPS as fallback. Persists runs via TrackRepository (:data).
    The phone-GPS PositionSource (Android FusedLocationProvider) is the
    one Android-specific piece in this area and is wired in at the app
    layer.


5. DATA FLOW
-------------------------------------------------------------------
Performance pipeline:
  :comm:transport (lines)
    -> :comm:nmea (TelemetrySample)
    -> :logic:timing (throttle to 1 Hz)
    -> :logic:filtering (drop bad points)
    -> :data (SampleRepository, persist) + :logic:calculation (matrix/curves)
    -> :ui (live marker + target curves on the polar canvas)

Position / tracking pipeline:
  PositionSource [N2K position (from :comm:nmea), preferred]
                [phone GPS (FusedLocationProvider), fallback]
    -> :tracking (group into runs, last 3, speed -> color)
    -> :data (TrackRepository, persist)
    -> :ui (speed-colored trace on the osmdroid map)

Settings drive wiring: :app reads Flow<Settings> and a factory selects
the matching Transport (comm type) and parser (protocol). Adding a new
protocol, transport, or position source later = one new implementation
module + one enum value + one factory branch; nothing else changes.


6. CORE FUNCTIONAL REQUIREMENTS
-------------------------------------------------------------------
Data management (historical logging)
  * Local caching of filtered SOW, TWS and TWA at 1 Hz.
  * Cleansing filters that pause/drop logging on spikes, tacks/jibes,
    or active engine PGNs, to protect target accuracy.
  * Target array construction: a TWS(0-30) x TWA(1-360) matrix holding
    the maximum historical speed per cell.

Visualization & UI layout
  * Radial grid: 360-degree plot centered on the vessel, axes every
    30 degrees (0, 30, 60 ... 360).
  * Concentric distance rings defining the speed scale, capped 0-30 kn.
  * Target line overlay: multi-colored polylines, one curve per wind-
    speed tier (e.g. 10 kn, 15 kn, 20 kn), each the max historical speed
    for that tier.
  * Live performance indicator: a prominent marker mapping the boat's
    instantaneous TWA/TWS/SOW over the historical curves.

Tracking
  * Records GPS position into runs; retains the last 3 runs.
  * Position sampled at a configurable interval (track accuracy, 1-5 s).
  * Each point stores SOG, COG and true heading (0-360 deg), viewable on
    the map.
  * Trace rendered on a nautical map (osmdroid; OSM + OpenSeaMap),
    colored by speed band (configurable, e.g. 0-3 kn yellow,
    3-6 kn orange, ...).

Logging
  * Rolling diagnostic log files, size configurable in settings.
  * Compressed (gzip) and exportable by email.

Configuration
  * Protocol, communication type, UI (scale, color, language, night
    mode), tracking on/off, speed-color bands, map overlay, and log
    file size — all user-configurable and reactive.


7. DEVELOPMENT MILESTONES
-------------------------------------------------------------------
M0 - Scaffolding
  Create the Gradle multi-module project (all 12 modules), wire the
  dependency graph, version catalog, and an empty app that builds and
  launches. Stand up :config (needed to select transport/protocol).

M1 - Communication & parsing
  :core contracts + models; WiFiTransport (socket, background coroutine,
  reconnect, connection state); :comm:nmea parser for performance and
  position PGNs with unit tests; foreground Service; :logging; a minimal
  screen that logs received samples to prove reception.

M2 - Filtering, persistence & calculation
  :data Room schema + repositories; :logic:timing (1 Hz); :logic:filtering
  (cleansing); :logic:calculation (matrix + target curves); full
  performance pipeline wired end to end.

M3 - Polar UI & tracking
  :ui Compose polar canvas (radial axes, rings, target polylines, live
  marker); ViewModels exposing StateFlow; :tracking runs + the osmdroid
  map trace (OSM + OpenSeaMap, speed-colored); settings screens wired
  into :config.
